# 为 AI 准备知识库

嵌入式的资料多、杂，而且分散。AI 查资料、写代码、检查硬件、对照规范，都依赖它能读到的资料。所以动手之前，先为 AI 准备一个知识库，让它在需要的时候自己检索。这一步决定了后面所有环节的上限。

## 要准备的资料

| 类别 | 例子 |
| --- | --- |
| 芯片 | 数据手册（datasheet）、用户手册（user manual）、勘误表、应用笔记 |
| 硬件 | 原理图、网表、BOM、所用元器件的手册 |
| 协议和标准 | 总线协议标准（例如 LIN 的 ISO 17987）、一致性测试规范 |
| 客户要求 | 整车厂规范、需求文档 |
| 已有代码 | 参考工程、协议栈、厂商例程 |

## 整理方法

1. **尽可能把资料收集齐**，按统一的目录存放。
2. **全部转成 Markdown。** 这种格式对 AI 更友好，检索快，读得准。
   - PDF：先用 OCR 模型识别成文本草稿（见 [tools.md](tools.md) 的“资料整理”），再让 AI 校准内容、整理格式。
   - Word、Excel：直接让 AI 转换并整理。
3. **做索引文件**，说明每个文件讲的是什么。AI 遇到问题先看索引，就知道该去哪里查。
4. **让 AI 交叉比对资料**，有矛盾的地方列出来，交给人审核。不同版本的手册常常互相矛盾，以实测为准。
5. **把规范整理成需求清单。** 涉及总线和诊断的要求单独提取出来，以后让 AI 拿代码逐条对照。
6. **在项目说明文件里写明知识库的位置和索引文件名**，以后的会话一开始就能找到。

## 注意

- 规范不全，AI 就查不出差异；资料转错了，AI 就会照着错的去改。转换后要抽查。
- 机密资料（客户规范、未公开的芯片文档）只放在本机，不要上传到公开的仓库或云端服务。
